# Design

## Context

骨架层已给出每步的时间戳、耗时、状态码、token 用量与增量分类。它还给出判定理由、压缩与末行更新标记、分歧行数。轮次给出编号、起始时间、压缩与重试与失败计数、旁路步数。这些字段全部由指纹与记录侧列算出,零解析。背景与动机见 `proposal.md`。

约束:

- 网关只存请求,不存响应。工具的客户端执行时间没有独立字段,只能由相邻两步的时间戳差推得。
- 形态基准是 `docs/trail-view.html`(admin-console 规范硬约束)。新增形态必须先出现在原型里。
- 前端是 Vite + Vue,产物嵌入二进制。不引入图表库,依赖最小化是项目规则。
- 派生结果不落盘,视图数据在查询时重算。

## Goals / Non-Goals

**Goals:**

- 读者在轮次内看出时间结构,并优先看到失败。
- 一行概括一轮做了什么,每段可跳到对应步。
- 口径与代价写进界面:哪些是实测、哪些是推断、哪些要解析。
- 原型与实现同步,不出现两套形态。

**Non-Goals:**

- 不做金额与计费。项目没有价格表,加成本列要新增配置与规范。
- 不做自动轮询刷新。本次只保证「一旦刷新也不打断阅读」。
- 不改推断规则。分类、判定理由与分组行为保持不变。
- 不存响应体,不改存储结构,不新增依赖。

## Decisions

### D1 时间轴偏移在服务端算,前端不解析时间戳

骨架每步新增 `at_ms`(相对本轮轴起点的毫秒偏移)。轮次新增 `duration_ms`。条长直接用该步已有的 `latency_ms`,不另存同名值。

理由:前端解析 RFC3339 会引入时区与格式风险。放在 Go 侧可表驱动单测,两个整数零解析。备选方案我否掉三个。前端解析 `ts` 会重复实现口径。新增派生耗时列违反「派生不落盘」。另存 `span_ms` 与其值恒等的 `latency_ms` 重复。

### D2 轴的跨度取本轮全部请求,含旁路步

轴起点取本轮最早一步的时间戳。轴终点取最晚一步的结束时间(时间戳 + 耗时)。旁路步照常画条,用弱化样式。

理由:旁路请求真实占用墙钟时间。隐藏它会得出错误的时间结构。代价是轴上的总时长与轮级统计口径不同,故轴注与图例 **必须** 写明「含旁路请求」。轮级计数仍只统计主路步。

### D3 空隙不另存字段,由条的位置自然形成

两根条之间的空白就是工具执行与等待。口径沿用只写公式:`下一 step 的 ts − 本 step 的 ts − 本 step 的 latency_ms`。负值截断为 0(与既有 `gapMs` 一致)。

理由:再存一个 gap 字段会与位置信息重复。两份数据可能自相矛盾。

### D4 亚秒步保底 0.6% 轴宽

按真实比例,快步骤在轴上会缩成不可见的一点。保底后位置仍可辨认。代价是极短步的条长不再成比例,故条宽定位为位置指示,数值一律由文字给出。

### D5 极值只标两个:最慢与最多 token

判据分别是 `span` 最大与 `usage_in + usage_out` 最大。同一步两项都满足时给两个标签。理由:读者要找的是「卡在哪」与「贵在哪」。标签再多就失去指向。两个判据都是实测值。

### D6 失败优先:判据只取记录侧,首次展开自动打开

判据沿用既有 `failed()`:状态码 ≥400,或记录侧 `error_kind` 非空。轮次首次展开时,含失败的步自动打开。「首次」按轮次记忆,已自动打开过就不再改动读者的折叠选择。失败清单放在轮次顶部,每条给位置与原因,点击后滚动到该步并居中。

备选方案我否掉两个。每次展开都自动打开会覆盖读者的选择。只处理工具失败会漏掉 HTTP 失败。

### D7 故事线在服务端生成,工具段由前端追加

骨架级段序列固定为:首步分类 → 行数合计 → 首个细分标记 → 失败计数。每段可带 `seq`,界面据此做跳转。时长与 token 作为尾注由界面渲染,沿用现有口径。

工具段属渐进填充。digest 到达且调用数大于 0 时,前端把它插在「行数合计」之后。未到达时不显示该段,不显示 0。

理由:骨架能覆盖的段放在 Go 侧可测。工具数依赖 digest,放前端可避免二次请求。段文本只允许重述既有判定与实测值。

### D8 分类分布:段是分类,细分另列

骨架新增 `kinds`,给出 6 个分类各多少步。分项之和等于步数。细分标记(摘要压缩、上下文清零、末行更新)另列计数,不并入分项之和。

理由:细分是分类内部的形态。混算会让分项之和超过步数。

### D9 图例单一来源,原型与实现共用文案

图例分三组。线型:实线=实测,虚线=推断,虚线灰框与虚线下划线=需解析。分类徽标:追加 / 分叉 / 末行更新 / 改写 / 无重合 / 重复。细分标记:摘要压缩 / 上下文清零。每项标明实测或推断。

实现里写成一张常量表。原型同步同一份文案。冒烟脚本断言两处一致,并断言构建产物含同一批文案。现状是原型只有说明段、实现没有图例,两处各写一份必然漂移。

### D10 数值纪律与代价文案

推断值在文本里带口径,沿用既有先例(`末行扩展 +26B`、判定理由)。缺失或不可得的数值统一显示「—」,与 0 区分。渐进加载的入口写明代价:要解析的消息行数。数据取自骨架已有的行数列,不额外请求。

### D11 阅读连续性:展开集合移出数据层

现状是 `load()` 清空 `openTurns` 与 `openSteps`。改为按会话保持展开集合,数据重载不影响它。同时保持滚动位置,数据更新不改变滚动容器位置。

现状没有轮询,问题未暴露。一旦加刷新就会打断阅读。

## Risks / Trade-offs

- [轴含旁路步,与轮级统计口径不同] → 轴注与图例写明「含旁路请求」。轮级计数仍只统计主路。
- [条宽保底后视觉不成比例] → 数值由文字给出,条宽只作位置指示。
- [故事线退化成营销话术] → 段文本只允许既有判定与实测值。新增语义要走提案。
- [原型与实现漂移] → 冒烟脚本断言图例文案与新形态存在。原型保持为规范形态基准。
- [骨架字段膨胀] → 只加 `at_ms`、`duration_ms`、`story`、`kinds`。全部零解析。

## Migration Plan

只增字段,不改已有字段,旧前端仍可用。无数据迁移,无回填。原型与实现同批更新。回滚方式是回退本次提交:新增字段无人读取即无影响。

## Open Questions

- 轴刻度单位与标签密度(秒或毫秒、几个刻度)按真实数据定。该选择不改变规范、方案与任务拆分。

# Proposal

## Why

轨迹视图目前只有文字。每步给一个耗时数字,失败藏在折叠层里,轮次只有一行标题。读者看不出时间花在哪一段,也找不到失败步。网关要回答的核心问题是「请求卡在哪一段」,当前视图回答不了。

## What Changes

- 新增**轮次时间轴**。轮次内每条步一根条,共用一条轴。轴上标出最慢的步与最多 token 的步。轴两端标 `0s` 与总时长。
- 新增**失败优先呈现**。轮次首次展开时,含失败的步自动打开。轮次顶部列出本轮失败,每条可跳到对应步。
- 新增**轮次故事线**。它由已有指纹字段生成一行确定性叙述(新输入 → 追加 N 行 → N 次工具 → 压缩 → 时长)。每段可点,跳到对应步。故事线只重述既有判定,不引入新语义。
- 新增**视图图例**。图例说明三种线型的含义:实线为实测,虚线为推断,虚线灰框与虚线下划线为需解析。图例同时列出分类徽标与细分标记的含义。
- 新增**会话分类分布条**。它按增量分类给出各多少步。分项之和等于步数,细分标记另列。
- 新增**数值呈现纪律**。同一事实只在一处给数值。推断值在文本里带口径。缺失值统一记为「—」。
- 渐进加载的入口写明代价。它给出要解析的行数,替代「需解析可渐进填充」这类抽象说法。
- 展开状态与滚动位置 **不得** 随数据重载丢失。
- 形态基准 `docs/trail-view.html` 同步覆盖以上形态。

**BREAKING**: 无。骨架接口只增字段,不改已有字段。

## Capabilities

### New Capabilities

无。本变更只扩展现有控制台视图。

### Modified Capabilities

- `admin-console`: 轨迹视图新增时间轴、失败优先呈现、故事线、图例、分类分布条与数值呈现纪律。形态基准同步更新。

## Impact

- 代码:`pkg/admin/trace_json.go`、`web/src/views/TracePanel.vue`、`web/src/api.ts`、`docs/trail-view.html`。
- 接口:`GET /console/api/traces/{session_id}` 骨架返回新增字段。只增不改,旧前端仍可用。
- 依赖:无新增。
- 规范:`admin-console` 增量。轨迹推断规则不变,故事线只重述既有判定。

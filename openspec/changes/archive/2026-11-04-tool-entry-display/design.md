# Design

## Context

见 `proposal.md` 的 Why。工具事件表已有每次调用的开始与结束时刻，按 `tool_call_id` 配对即得耗时。

## Goals / Non-Goals

**Goals:**

- 条目一眼可读：名称、动作、耗时、结果。
- 展开后信息完整。

**Non-Goals:**

- 不在条目里显示推断来源。
- 不为摘要单独建索引。

## Decisions

### 1. 耗时由前端按标识配对

后端在 step 明细里多给 `tool_call_id`。前端用会话级工具事件接口取耗时，按标识匹配。理由：明细与事件来自两条查询，各自职责不变。

### 2. 参数摘要取动作字段

优先取 `command`、`file_path`、`pattern`、`query`、`url`、`description`。都缺失时取第一个字符串字段。理由：这些字段直接说明工具做了什么。

### 3. 规范重写而非追加

旧要求把推断来源写进了行为描述。追加一条新要求会与旧要求冲突，因此整体重写「轨迹查看」。

## Risks / Trade-offs

- **摘要被截断** → 展开可见完整入参。
- **无事件时无耗时** → 显示未知，不估算。

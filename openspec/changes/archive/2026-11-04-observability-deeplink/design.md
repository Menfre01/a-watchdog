# Design

## Context

见 `proposal.md` 的 Why。`Observability.vue` 用 `selected` 一个 ref 在列表与详情之间切换,`v-if` 会卸载列表。轨迹面板由 `TracePanel.vue` 承载，单个会话可能有数百个节点，自己做分层展开。项目没有路由依赖，内容区宽度由孤岛式布局约束。

## Goals / Non-Goals

**Goals:**

- 地址栏成为导航状态的唯一来源。
- 返回列表不丢位置与筛选。
- 键盘用户不依赖「查看」按钮也能进入详情。

**Non-Goals:**

- 不引入 vue-router。
- 不把面板内部的展开状态(轮次、步)写进地址栏。
- 不改轨迹面板的渲染结构。

## Decisions

### 1. 手写 hash 路由

新增 `web/src/route.ts`:从 `location.hash` 解析出 `{ sessionID, panel }`,并提供 `buildHash` 与 `subscribe(listener)`(监听 `hashchange`)。路径形如 `#/observability/<encodeURIComponent(session_id)>?panel=trace|tools`。

理由：两段状态用 hash 足够。引路由库要为一次导航付一个依赖。备选是 history API,它需要处理 404 回退与服务器配置，收益只是 URL 更干净。

### 2. 列表保活，轨迹即卸

列表用 `v-show` 控制显隐，详情在 `selected` 有值时渲染。轨迹面板保持挂载即卸，不套 `KeepAlive`:它的节点量远大于列表。

理由：列表节点便宜且必须保活才能恢复滚动。轨迹保活会让多个会话的 DOM 同时存在，正是分栏方案被否掉的原因。

### 3. 行入口是链接，整行点击是增强

会话标识单元格改为 `<a :href="buildHash(id)">`,点击行其余位置同样导航。删除「查看」按钮。

理由:`<a>` 自带键盘操作、右键新开、状态栏目的预览。整行点击只是鼠标便利。链接显式改变地址栏，不经过组件内部状态。

### 4. 深链时按标识回填摘要

详情头部需要 steps 与 token。若地址栏的会话不在当前列表(例如刷新后列表尚未加载),按 `q=<完整标识>` 查询一次并取精确匹配。取不到则退回只显示标识与轨迹面板。

理由：深链必须能独立打开，不能依赖先加载全表。

### 5. 返回时恢复滚动与焦点

进入详情前记录列表滚动位置与触发行标识。返回时恢复 `scrollTop`、把该行滚进视野，并把焦点还给该行的链接。列表隐藏期间不保留读屏播报。

### 6. 详情头部只放会话信息

头部只给会话标识、Agent、密钥与时间范围，不放 steps 与 token。

理由：轨迹统计卡已经给出总计与主路/旁路拆分。两处并列会让同一数值出现两次，违反「同一事实只在一处给出」的纪律。实现过程中曾把统计补进头部，复审时撤销。

## Risks / Trade-offs

- **hash 变化触发重复渲染** → 订阅回调只在 `sessionID` 或 `panel` 变化时更新，避免每次 `hashchange` 都重取数据。
- **深链的会话已被删除或标识非法** → 显示「会话不存在」并给返回列表入口，不抛错。
- **隐藏列表仍可被读屏访问** → `v-show` 只改 `display`,需额外 `inert` 或 `aria-hidden`,否则读屏仍能进入隐藏表格。
- **浏览器后退与组件状态竞争** → 以 hash 为唯一来源，组件不再自己记 `selected`。`selected` 只是 hash 的派生值。

## Migration Plan

无迁移。回滚为删除路由模块并恢复 `selected` 局部状态与「查看」按钮。

# Design

## Context

见 `proposal.md` 的 Why。分类分布由骨架的 `kinds` 字段驱动,步徽标与图例另走 `KIND_TEXT` 与 `trailLegend`。

## Goals / Non-Goals

**Goals:**

- 统计卡只保留时间口径。
- 分类仍可在步级别阅读。

**Non-Goals:**

- 不删后端分类计算与接口字段。
- 不改图例与徽标文案。

## Decisions

### 1. 只删界面块,不删数据

`kinds` 字段继续返回。理由:分类对排查缓存前缀有用,删数据等于丢掉能力;删界面只是换一种阅读入口。

### 2. 图例保留分类条目

图例仍解释各徽标含义。没有分布条,图例里的分类条目对应步上的徽标,不指向已删除的图形。

## Risks / Trade-offs

- **读者失去全局分类视图** → 需要时按步展开;若日后要回,重新提案。
- **图例文案提到分布条** → 需检查并改为只指向徽标。

## Migration Plan

无迁移。回滚为恢复统计卡分布块。

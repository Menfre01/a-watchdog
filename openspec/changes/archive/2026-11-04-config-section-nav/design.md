# Design

## Context

见 `proposal.md` 的 Why。当前侧栏由 `App.vue` 的 `tabs` 数组驱动,视图靠 `v-if` 切换;接入与模型目录各自渲染页头与主操作按钮。三个配置区的数据量都不大,一张表各自就能装下。

## Goals / Non-Goals

**Goals:**

- 侧栏只表达两个模块。
- 三个配置区同页可见,一眼能看全。
- 孤岛之间靠留白分层,不靠分隔线。

**Non-Goals:**

- 不引入路由,不把选择状态写进 URL。
- 不改后端接口。
- 不做可拖动、可折叠的孤岛布局。

## Decisions

### 1. 孤岛铺开,不用分页

三个管理区同页呈现:接入占满一行,模型目录与客户端密钥在宽屏并排、窄屏纵向堆叠。理由:三块都是「列表 + 一个主操作」,分页只是多一次点击,还让人看不到其余两块的状态。

备选是分页或折叠面板。分页把同类操作割裂;折叠面板默认收起,等于把内容藏起来,同样不符合「一眼看全」。

### 2. 孤岛自带标题与主操作

每个孤岛是一个 `section`,内部结构固定:二级标题在左,主操作在右,下面是该区的表格或空态。配置模块只给一级标题「配置」,不再重复分页名。

### 3. 孤岛用令牌表达层次

新增两个令牌:`--r-lg`(10px)与 `--shadow-card`。孤岛底色用 `--surface`,页面底色用 `--bg`,边框用 `--line`,阴影在暗色下取低透明度,避免发灰。

### 4. 表格留在孤岛内横向滚动

孤岛宽度有限,表格仍用 `.table-scroll` 包住,保证窄屏只在表内滚动。

## Risks / Trade-offs

- **页面变长** → 三块纵向堆叠时需要滚动。宽屏并排可缓解;接入表本身七列,难以再压缩。
- **暗色下阴影发灰** → 阴影只做轻微层次,主要靠底色差与边框;必要时可关掉阴影只留边框。
- **小屏三块串成长页** → 分页反而更省滚动,但违背「同页可见」的目标;保留纵向堆叠作为取舍。

## Migration Plan

无迁移。回滚为恢复分页与五项侧栏。

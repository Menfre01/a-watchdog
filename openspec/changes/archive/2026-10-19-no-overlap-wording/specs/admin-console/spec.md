# Spec Delta

## ADDED Requirements

### Requirement: 分类的显示用词

控制台 **必须(MUST)** 用「无重合」称呼分类 `chain`,**不得** 用「新链」称呼它。该分类的含义是:本步与**同链**上一步既无共同前缀,也无共享尾部。

判定理由 **必须** 陈述这一事实。理由 **不得** 出现「新链」这一说法,那会与链归属的「链」混同。

轮级标记 **必须** 改称「不相交」:该标记同样由分类 `chain` 推导,含义是「本轮与上一步不相交」。

内部键 **必须** 保持 `chain`:改词 **不得** 改动接口、数据与历史快照。

#### Scenario: 徽标与分布条用新词

- **WHEN** 读者查看某步的分类徽标或会话头的分类分布条
- **THEN** 该分类显示为「无重合」,不显示「新链」

#### Scenario: 判定理由陈述事实

- **WHEN** 读者查看该分类的判定理由
- **THEN** 理由说明它与同链上一步无共同前缀也无共享尾部,并且不出现「新链」这一说法

#### Scenario: 轮级标记改称不相交

- **WHEN** 某轮由该分类的步开启
- **THEN** 轮级标记显示为「不相交」

#### Scenario: 内部键不变

- **WHEN** 比较改词前后的接口响应
- **THEN** 分类键仍是 `chain`,只有显示词与文档用词变化

### Requirement: 链归属与内容分类的分工写清楚

视图 **必须(MUST)** 让读者分清两件事:链归属决定「这是哪一条链」,内容分类决定「这一步与同链上一步重合多少」。

判定理由或图例 **必须** 至少在一处说明:链归属用稳定指纹(system 前缀加首条 user 前缀),内容分类用整行字节。两者判据不同,故「同一条链」与「零重合」可以同时成立。

#### Scenario: 两件事的说法不混同

- **WHEN** 读者看到某步被标为「无重合」
- **THEN** 界面说明这一步仍属于原链,并指出链数见会话头的链汇总

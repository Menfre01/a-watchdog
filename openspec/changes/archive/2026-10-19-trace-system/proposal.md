# Proposal

## Why

C1 让请求稳定流过网关并留下元数据记录(模型、状态码、延迟、token),但**看不到上下文本身**:一次会话里 agent 每轮发了什么消息、调用了哪些 tool、每次调用的入参与结果是什么,当前都不可见。C2 把这批真实流量(from Claude Code 等)变成可回看的会话数据。

## What Changes

- **原始层(不可再生,全量保真)**:每次请求的原始请求行(method/path/query)、入向请求头与 body 原样存储(gzip 压缩,SQLite,与请求记录关联),**含被鉴权拒绝/被短路的请求**;不解析、不改写、不剔字段——唯一例外是凭据类头的值脱敏(头名保留)。
- **事实层(记录时异步固化)**:协议无关的规范化 messages 快照(ndjson,一行一条 `{role, blocks[]}`),**最大保真**——thinking/reasoning 家族全部进主干、无法识别的字段不丢弃、`cache_control`/`signature` 保留、`tool_use` 与 `tool_result` 的标识和内容原样保留、二进制(图片/文档字节)以 hash 引用、`tools` 定义不进主干;仅会话型推理端点生成(辅助端点如 `count_tokens` 不产快照);解析规则升级时可从原始层全量重放重建。
- **行指纹(比对专用)**:每条快照附行指纹序列(每行内容的哈希,8 字节/行);增量分类只读指纹,不触发解压与 JSON 解析。
- **session 判定(仅显式标识)**:按协议取会话标识头(Claude Code 的 `x-claude-code-session-id`;Codex 的 `session-id`/`thread-id`,两种拼写都接受),标识经长度与字符白名单规范化;未携带或不合规时归入按天分桶的匿名会话。判定结果与**判定理由**(`session_note`)随快照落盘。**链合兜底(按消息内容推断会话延续)不在本次范围**——主流客户端都携带标识头,其复杂度远高于收益。
- **推断层(查看时计算,不落库)**:从快照推断会话结构——相邻 step 的行指纹比对给出增量分类(追加/重复/分叉/改写/无重合),连续重复构成重试组并按组内序号计数;tool 调用按 `tool_use` 与 `tool_result` 的标识配对成明细(名称、入参、结果、成功失败);轮次(Turn)分组由「追加且尾部含非 `tool_result` 的 user 消息」推断,并排除客户端注入内容;规则全部可迭代,改规则只改代码、不需重放数据。
- **控制台新增「可观测」菜单(只读)**:三个视图——**会话列表**(跨会话入口,按标识/时间/key 过滤;不含轮次数)、**轨迹**(轮次 → step 骨架 → 展开加载 tool 明细与 messages;摘要压缩给出前后对照、分叉给出两侧内容对照、旁路链以轮次内 tab 分列,被拒请求带网关侧归因、上下文清零与无重合各有独立标记)、**工具**(会话级聚合,支持名称 / 状态 / 来源筛选)。轮次分组、增量分类与重复计数标注为推断;tool 阶段耗时以轮间间隔近似并标明口径。视图形态以 `docs/trail-view.html` 为基准。
- **捕捉管线与 C1 记录同款异步**:有界队列(深度按元素携带原始 body 的内存上界下调)+ 写协程,压缩/解析/落库全在异步侧,不阻塞请求;写失败不影响请求与记录。
- **明确不做**(维持既有定位):不做行级 LCS diff 与压缩事件分析,不做判定重算与维护审计,不做概览数字块,不做 OpenTelemetry 导出;不引入 go-git、文档数据库、docker-compose;不改变任何对外协议行为(纯旁路能力)。

## Capabilities

### New Capabilities

- `trajectory-capture`: 原始保真存储、规范化快照生成、session 判定与异步捕捉管线
- `trajectory-analysis`: 增量分类、轮次推断与 tool 调用抽取——全部查看时计算、可重放

### Modified Capabilities

- `admin-console`: 新增轨迹只读视图(会话列表 / 轮次时间线 / 单轮详情与 tool 明细)

## Impact

- 存储:新增迁移(0003)与两张表(原始请求、快照);sqlc 查询扩展;原始层 body 与规范化快照各存一份(gzip),叠加行指纹列(约 +13%),按单请求约 30KB 量级折算个人使用年增约 2-4GB
- 代码:新增 `pkg/trace`(规范化与推断)与捕捉环节,控制台与记录管线小幅扩展;压缩用标准库 gzip——**零新增第三方依赖**
- 对既有行为:C1 的请求处理、记录、控制台配置能力不变;轨迹捕捉失败只影响轨迹完整性,不影响请求与记录
- 验收闭环:一场真实 Claude Code 会话 → 控制台看到完整轮次、每轮 tool 调用明细、耗时与 token 用量

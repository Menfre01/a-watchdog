# Spec Delta

## ADDED Requirements

### Requirement: 可观测菜单

控制台 **必须(MUST)** 提供「可观测」菜单,由**三个只读视图**组成:**会话列表**(跨会话入口)、**轨迹**(单个会话的层级展开)与**工具**(会话级聚合与筛选)。三个视图共用会话级查询缓存;任何视图 **不得** 修改原始层、快照与请求记录,也 **不得** 为展示写入派生数据。视图的层级、字段与视觉语言(实线为实测值、虚线为推断、虚线灰框与虚线下划线为需解析可渐进填充) **必须** 以 `docs/trail-view.html` 为形态基准。

#### Scenario: 菜单结构

- **WHEN** 管理员打开可观测菜单
- **THEN** 可见会话列表、轨迹与工具三个视图;点击会话列表中的会话可进入该会话的轨迹

#### Scenario: 只读约束

- **WHEN** 通过可观测菜单查看任何视图
- **THEN** 原始层、快照与请求记录均不被修改,展示过程不产生派生数据写入

### Requirement: 会话列表视图

会话列表 **必须(MUST)** 支持按标识前缀、时间范围与 client key 过滤;每行显示会话标识、判定来源与判定理由、首见与末见时间、step 数与累计 token(`steps` 即该会话的请求数:会话归属由快照承载,二者恒等)。列表 **不得** 呈现轮次数——推断轮次需要对每个会话做指纹比对与首行解析,成本随会话数线性放大;轮次数由轨迹视图给出,列表页 **必须** 说明这一取舍。

#### Scenario: 列表与过滤

- **WHEN** 管理员按标识前缀过滤会话列表
- **THEN** 只列出匹配的会话;每行显示判定来源与理由、首末时间、step 数与累计 token

#### Scenario: 不含轮次数

- **WHEN** 管理员打开会话列表
- **THEN** 列表不显示轮次数(该口径由轨迹视图承担),并可见说明其成本原因

### Requirement: 轨迹查看

轨迹 **必须(MUST)** 提供单个会话的层级视图:轮次(序号、标题、起始时间、step 数、汇总用量,以及是否含压缩、重复次数、失败步数与 tool 调用数)→ step 骨架(时间、耗时、状态、token 用量、重复标记、增量分类与压缩标记及行数与长度变化、新增行数、判定理由)→ step 展开后加载 tool 明细(名称、入参、结果、状态)与 messages(默认本轮新增,可切换全量)。

tool 调用 **必须** 以独立条目呈现于发起轮与结果轮之间,可展开查看入参与结果:发起轮为推断(响应不落盘),结果来自下一轮请求。

摘要压缩 **必须** 给出前后对照:压缩前后的消息序列与行数,以及保留、移除、新增的行数;被移除的内容 **必须** 可展开查看。**分叉** **必须** 给出**差异块**(按 LCS 求出、与同链上一步比较):每块标明类型(改动 / 删除 / 新增)、两侧的行号范围与字节数,以及该处每一行的实际消息内容;每块 **必须** 可独立折叠,单块时默认展开;消息被删除时只给出旧侧内容并标明新侧无内容。纯追加 **不得** 产生差异块(其内容由「本轮新增消息」呈现)。**不得** 仅凭长度变化推断「压缩」或「改写」等语义。**上下文清零** 与 **无重合** **必须** 有各自独立的标记与判定理由(旁路链 **不得** 标「上下文清零」:该语义只对主对话成立,旁路请求没有"上下文"可言);会话首步与后续的无重合 **必须** 用不同文案区分(两者同属「无共同前缀也无共享尾部」,语义不同),不得把首条快照的文案套用到无重合上。

时间线骨架 **必须** 只解析各步的新增区间、不解析历史消息(gzip 不支持随机访问,解压本身无法避免);轮次的标题与 tool 调用数 **可以** 在骨架渲染后异步填充,**不得** 阻塞轮次与 step 的呈现。记录侧 `error_kind` 非空时,该步 **必须** 呈现网关侧归因(如鉴权拒绝、模型未路由、上游中断)。会话归属由快照承载,无快照的请求不出现在轨迹中(见 trajectory-capture),视图 **不得** 声称覆盖全部请求。轮次分组、增量分类与重复计数 **必须** 以一致的方式标明为推断(统一样式或图例,不逐条重复标注);tool 调用的耗时 **必须** 以轮间间隔近似并标明该口径(含客户端本地执行时间与人工思考时间)。

#### Scenario: 查看完整轨迹

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 从首轮至最新逐轮可见,step 骨架即时显示耗时、token 用量、重复标记与增量分类;展开后加载 tool 明细与 messages

#### Scenario: 重复步可见

- **WHEN** 会话中出现与上一步内容完全相同的请求
- **THEN** 该步按组内序号呈现(如「第 2/3 次相同」),并可见其自身状态码与判定理由

#### Scenario: 摘要压缩可对照查看

- **WHEN** 管理员查看某个被标记为摘要压缩的 step
- **THEN** 可见压缩前后的行数与消息序列对照,以及被移除区间的内容(展开时加载)

#### Scenario: 差异块可查看

- **WHEN** 管理员查看某个分类为分叉的 step
- **THEN** 可见各差异块的类型与两侧行号范围,展开后可见该处每一行在相邻两步的实际内容

#### Scenario: 消息被删除可辨识

- **WHEN** 本步相对同链上一步删除了若干消息
- **THEN** 差异块标记为「删除」,只给出旧侧行号与内容,新侧标明无内容

#### Scenario: 上下文清零可辨识

- **WHEN** 主对话在新一轮请求中几乎清空历史(如 `/clear`)
- **THEN** 该 step 有独立的「上下文清零」标记与判定理由,不与普通无重合混同;旁路链不产生该标记

#### Scenario: 无重合可辨识

- **WHEN** 主对话某 step 的消息与上一步既无共同前缀也无共享尾部
- **THEN** 该 step 标记为「无重合」并给出判定理由

#### Scenario: 被拒请求可辨识

- **WHEN** 某请求被鉴权拒绝(无上游调用)且其请求体可解析
- **THEN** 该步在其所属会话的轨迹中可见,并标明网关侧归因,不因其被拒而省略

#### Scenario: 轮次提示

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 每个轮次显示 step 数、汇总用量、是否含压缩、重复次数与失败步数;标题与 tool 调用数可稍后填充,不阻塞列表呈现

#### Scenario: 轮次标题渐进填充

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 轮次先呈现骨架,标题与 tool 调用数稍后填充;标题取不到时为空,不阻塞呈现

#### Scenario: 查看单步 messages 与 tool 明细

- **WHEN** 管理员打开某个 step
- **THEN** 默认可见本轮新增的 messages 与继承行数,可切换查看全量;每个 tool 调用的名称、入参、结果与状态可见

### Requirement: 工具聚合视图

控制台 **必须(MUST)** 提供**会话级**的工具聚合视图:按工具名汇总调用次数、状态分布(成功 / 失败 / 结果未见)、近似间隔与发起的轮次;视图 **必须** 支持筛选:工具名(片段匹配)、状态、来源(内置 / MCP)。「结果未见」的调用 **必须** 单独呈现,且 **不得** 计入间隔统计。间隔 **必须** 标明为轮间近似(含客户端本地执行与人的思考时间)。聚合 **必须** 由快照现算,**不得** 为它额外写入源数据;跨会话的全局统计不在本变更范围内。

#### Scenario: 聚合与筛选

- **WHEN** 管理员打开工具视图并按状态筛选「失败」
- **THEN** 只列出存在失败调用的工具,汇总数字随筛选条件更新

#### Scenario: 结果未见单独呈现

- **WHEN** 某次调用在后续快照中找不到结果
- **THEN** 该工具行计入「结果未见」,且该次调用不参与间隔统计

#### Scenario: 来源可区分

- **WHEN** 调用的工具名带 `mcp__` 前缀(来自 MCP 服务器)
- **THEN** 其来源标为 MCP,可与内置工具分开筛选

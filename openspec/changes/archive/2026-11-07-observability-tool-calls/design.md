# Design

## Context

工具视图当前通过 `tool-calls` 摘要接口读取合并后的调用。后端合并两个来源：

- 轨迹分析里的 `trace.ToolCall`，带 `IssuedSeq` 与 `ResultSeq`。
- `GET /console/api/tool-events?session_id=...` 配对的开始/结束事件，含入参、结果、耗时。

工具事件是客户端 hook 上报的开始/结束事件，不是工具调用本身。工具调用可以从轨迹的 tool_use 与 tool_result 得到。缺少事件只影响耗时、审批与载荷，不影响调用是否出现。

## Goals / Non-Goals

**Goals:**

- 保留统计岛。
- 增加会话级调用列表。
- 支持工具名、状态、来源筛选。
- 支持按时间与耗时排序。
- 展开显示 step 上下文、工具入参与结果。

**Non-Goals:**

- 不做跨会话工具统计。
- 不计算工具成本。
- 不做调用列表分页或虚拟滚动。
- 不改现有统计口径。
- 不为工具事件新增数据库列。

## Decisions

### 1. 新增调用级接口，不把上下文塞进聚合接口

新增：

```
GET /console/api/traces/{session}/tool-calls
GET /console/api/traces/{session}/tool-calls/{tool_call_id}
```

第一个接口返回摘要，不返回完整结果。第二个接口返回单次调用的完整入参、结果与截断标记。

摘要接口调用现有 `analyzeSession` 取 `trace.ToolCall`，再读取 `ListToolEvents` 配对结果。两者按 `tool_call_id` 合并。

摘要接口返回：

- `tool_call_id`、工具名
- `issued_seq`、`result_seq`
- `source`：`local` 或 `mcp`
- `status`：成功、失败、结果未见
- `input_preview`
- `started_at`、`duration_ms`、`approval_wait`、`complete`

详情接口返回同一标识下的完整 `input`、`result` 与截断标记。

耗时、开始时间、审批标记来自工具事件。摘要中的入参摘要优先取事件上报值，缺失时用轨迹复原值补足。完整入参与结果只在详情接口返回。

### 2. 三类调用都要有确定行为

- **事件与轨迹都有**：完整合并，有 step 与耗时。
- **只有轨迹**：列出调用，状态取轨迹，耗时为 `—`，上下文可用。缺少事件不改变状态。
- **只有事件**：列出调用，`issued_seq` 与 `result_seq` 为 0，耗时可用，上下文不可用。只有开始事件时状态为结果未见。

只有事件、没有 step 的调用仍然有价值。能看工具名与耗时，展开后能看入参与结果，只是无法跳到轨迹。

### 3. 摘要列表、筛选与排序放在前端

接口一次返回当前会话的全部调用摘要。摘要含工具名、状态、来源、step、时间、耗时与入参摘要。完整入参与结果不进入摘要。前端用筛选条件过滤，并提供：

- 机器时间排序：按 `started_at`。
- 耗时排序：按 `duration_ms`，无耗时的调用始终排在末尾。
- 默认按开始时间降序。

筛选只作用于调用明细。统计岛始终保持全会话口径，避免状态筛选把成功或失败统计清零。摘要全部在内存中，列表使用虚拟滚动或分批渲染。

### 4. 展开上下文按需拉取

展开时先拉取调用详情，取得完整入参与结果。再调用现有接口取 step 上下文：

```
GET /console/api/traces/{session}/{seq}?ctx=...
```

显示发起 step 的请求 messages 与 response，并给出进入轨迹的链接，同时标明发起 step 序号。

结果 step 只作为跳转目标，不重复拉取结果请求。工具结果已在调用行内显示，避免一次展开触发两次大请求。

没有 `issued_seq` 的调用显示「上下文不可用」，不伪造 step。

### 5. 页面结构

工具视图改为：

```
工具统计岛
  主行:调用数、成功率、p95 耗时
  异常行:失败、结果未见、含审批，只在非零时出现
  有耗时工具 ≥2:耗时构成条 + 图例
  有耗时工具 =1:一行摘要
  覆盖:有耗时调用数 / 总调用数
工具调用明细
  筛选条
  排序控件
  调用表格
    展开行: step 请求 / 响应, 工具入参 / 结果, 轨迹链接
```

统计岛只给三个主指标与异常行，再按工具显示耗时分布。多工具时用带标签的构成条，单工具时退化为摘要行。统计与明细都从同一份合并调用计算，避免事件调用只在明细出现。

### 6. 状态与来源复用现有口径

- 状态取轨迹的 `ok / error / unseen`。没有轨迹时用事件状态。只有开始事件时标为结果未见。缺少事件不等于结果未见。
- 来源按工具名 `mcp__` 前缀判定，与现有 `sourceLabel` 一致。
- 结果未见不显示耗时，不伪装为成功。

## Risks / Trade-offs

- **调用列表过大** → 摘要列表使用虚拟滚动或分批渲染。详情按需加载，避免一次传输大量入参与结果。第一版不做服务端分页。
- **工具事件与轨迹不一致** → 事件有结果但轨迹未见，或相反。合并时以轨迹决定 step 与状态，以事件补耗时和载荷。测试覆盖三类合并。
- **上下文请求较大** → 只在展开时拉取一个 step，并限制上下文行数。结果 step 只给链接。
- **隐私** → 入参与结果可能含敏感内容。仍走管理员鉴权与现有轨迹访问边界，不新增公开接口。
- **统计与明细口径分叉** → 两者都从合并后的调用摘要计算。事件调用与轨迹调用都计入，测试覆盖只有事件的调用。
- **读者可能把构成条误读为会话时间占比** → 构成条标题写明「工具耗时构成」，并标注总耗时。界面不宣称它是会话时间占比。

## Migration Plan

- 新增只读接口，不改数据库。
- 前端先接调用列表，再启用上下文展开。
- 回滚时隐藏调用明细，统计岛保持原样。

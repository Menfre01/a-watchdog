# Design

## Context

见 `proposal.md` 的 Why。钩子载荷含 `tool_input` 与 `tool_response`。读取接口已按 `tool_call_id` 配对。

## Decisions

### 1. 加列而不是建表

载荷与事件同生命周期，加可空列即可。读取时按标识合并，不需要新查询路径。

### 2. 截断保留前缀

超过 256 KB 时截断 JSON 文本并标记。读取侧解析失败时退回字符串，界面标「已截断」。

### 3. 状态分三级

完成取结束事件且无错误标记。失败取失败事件或结果的错误标记。只有开始事件记未知。钩子层面不判断命令退出码。

## Risks / Trade-offs

- **大结果占空间** → 上限 256 KB 且 gzip。
- **Codex 无失败钩子** → 失败可能显示完成。以结果里的错误标记兜底。

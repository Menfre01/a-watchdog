# Design

## Context

见 `proposal.md` 的 Why。客户端密钥鉴权已在 `pkg/middleware/auth.go` 实现。控制台与网关共用同一份配置快照。工具执行在客户端，网关只有请求边界。

## Goals / Non-Goals

**Goals:**

- 三类客户端共用一个端点。差异收在适配层。
- 重复上报不产生重复行。
- 时长口径可追溯。边界类型与审批标记随记录落库。

**Non-Goals:**

- 本轮不改控制台界面。
- 不推算纯执行时间。客户端不给执行起止，网关也拿不到。
- 不做批量上报与离线缓冲。

## Decisions

### 1. 一个端点，适配器分流

请求带 `client` 查询参数，服务端据此选适配分支。Claude Code 与 Codex 的事件名相同，可直接映射。DSH 与未知客户端按规范字段读取。

备选是每个客户端一个路径。它让文档更好写，却会让鉴权与幂等逻辑复制三份。

### 2. 幂等靠唯一约束

`UNIQUE (client, tool_call_id, phase)` 加 `ON CONFLICT DO NOTHING`。重复上报由数据库兜底。

备选是先查后写。它在并发下会竞态，还要多一次读。

### 3. 会话标识补上密钥前缀

上报体里的 `session_id` 是客户端原始标识。落库前拼成 `<key_id>:<uuid>`，与既有会话对齐。密钥 id 来自鉴权结果，不由客户端提供。

### 4. 时长只在读取时配对

表里只存事件，不存时长。读取时按 `tool_call_id` 配对开始与结束，差值即墙钟差。晚到的结束事件也能立刻生效。

## Risks / Trade-offs

- **审批等待计入时长** → 记录 `approval_wait` 标记。后续可用权限事件扣除，当前先如实标注。
- **Codex 没有失败事件** → 失败调用可能只有开始事件。读取时显示为未完成，不推算。
- **端点可被伪造** → 事件只用于观测，不参与鉴权与计费。
- **写入放大** → 每次工具调用两条小请求。回环成本可忽略，后续可加批量上报。

## Migration Plan

新增 0004 迁移，只建表。回滚为删除表与端点。

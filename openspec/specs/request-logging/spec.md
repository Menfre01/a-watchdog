# request-logging

## Purpose

定义每请求记录的持久化行为与字段口径:记录哪些请求、记录什么字段,以及记录动作对请求处理的影响边界。记录是后续轨迹分析的数据基础,但其写入不得进入请求处理的关键路径。

## Requirements

### Requirement: 请求记录

系统 **必须(MUST)** 为每个到达网关的推理请求写入一条记录(**包括**被鉴权拒绝或被短路的请求),至少包含:时间、客户端 key 标识、入向协议、请求模型、实际 provider 与上游模型、响应状态码、延迟、流式标记,以及上游返回的 usage(如有)。

#### Scenario: 成功请求被记录

- **WHEN** 一次流式请求成功完成
- **THEN** 记录中存在该请求条目,含所选 provider/model、状态码、延迟与 token 用量

#### Scenario: 被拒绝请求也被记录

- **WHEN** 请求因无效 key 被返回 401
- **THEN** 该请求仍产生一条记录(标记鉴权失败),供后续排查

### Requirement: 记录不干扰请求

记录写入 **必须(MUST)** 与响应时序解耦:**不得** 因记录写库阻塞响应完成或改变响应内容;记录失败 **必须** 仅落入网关日志,**不得** 影响请求本身的结果。

#### Scenario: 记录失败不影响请求

- **WHEN** 记录写入发生错误(如存储异常)
- **THEN** 客户端仍正常收到完整响应,错误仅出现在网关日志中

#### Scenario: 不阻塞流式响应

- **WHEN** 流式请求进行中
- **THEN** 记录写入不参与响应流的转发时序

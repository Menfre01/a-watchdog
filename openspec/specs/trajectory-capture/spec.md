# trajectory-capture Specification

## Purpose
定义轨迹捕捉行为:原始请求保真存储、协议无关的规范化快照生成、session 判定,以及捕捉对请求处理的零干扰边界。

## Requirements

### Requirement: 原始层保真存储

系统 **必须(MUST)** 为每个到达网关的推理请求存储原始请求行(method/path/query)、入向请求头与请求体原文(gzip 压缩,持久化于数据文件),并与对应的请求记录关联;**必须** 同样覆盖被鉴权拒绝或被短路的请求。存储 **不得** 解析、改写或剔除任何字段——唯一例外是凭据类头的值脱敏(头名保留)——原始层是一切的保真底。

#### Scenario: 原始请求体可回溯

- **WHEN** 任一已记录请求被回溯
- **THEN** 能取回与客户端实际发出等价的原始请求体

#### Scenario: 被拒请求同样留存

- **WHEN** 请求因无效 key 被返回 401
- **THEN** 该请求的原始请求体同样被存储并与记录关联

#### Scenario: 请求头可回溯

- **WHEN** 任一已记录请求被回溯
- **THEN** 能取回其入向请求头(凭据类头的值为脱敏占位),session/agent 标识头原样可取

#### Scenario: 端点可区分

- **WHEN** 同一 messages 内容分别发往 `/v1/messages` 与 `/v1/messages/count_tokens`
- **THEN** 原始层可凭请求行区分两者,不被归为同一种请求

#### Scenario: 凭据不落盘

- **WHEN** 请求携带凭据类头(如 `Authorization`)
- **THEN** 原始层中该头的值为脱敏占位,不出现原文

### Requirement: 规范化快照生成

系统 **必须(MUST)** 为会话型推理请求生成协议无关的规范化快照——消息内容可解析的请求(含被鉴权拒绝、被短路者)如实生成并进入轨迹;辅助端点(如 count_tokens 类)**不得** 生成快照,仅保留原始层。每条消息一行(canonical JSON),类型化块结构;消息内全部内容 **必须** 保留——含各协议 reasoning 家族(thinking / reasoning / reasoning_content 等)、无法识别的字段与注解字段(`cache_control`、`signature` 等);tool 调用与结果 **必须** 保真:调用的标识、名称与入参、结果的标识与内容 **不得** 丢失或改写;二进制内容(图片/文档字节)**必须** 以引用形式进入快照(字节本体不进入);`tools` 定义 **不得** 进入主干。

#### Scenario: 跨协议同构

- **WHEN** 语义等价的消息分别以 OpenAI Chat 与 Anthropic Messages 协议发出
- **THEN** 两者生成的规范化快照在主干结构上同构(与协议差异解耦)

#### Scenario: 保真不剔减

- **WHEN** 请求包含 thinking 内容、签名或未知类型块
- **THEN** 快照中原样保留这些内容,不因无法识别而丢弃

#### Scenario: tool 调用保真

- **WHEN** 请求包含 tool 调用或 tool 结果
- **THEN** 快照保留调用的标识、名称与入参,以及结果的标识与内容,可供后续配对

#### Scenario: 可从原始层重放

- **WHEN** 解析规则升级需要重建快照
- **THEN** 可从原始层全量重放生成,不依赖请求重放

#### Scenario: 辅助端点不进轨迹

- **WHEN** 请求发往辅助端点(如 `/v1/messages/count_tokens`)
- **THEN** 原始层照常留存,但不生成快照、不出现在轨迹中

#### Scenario: 被拒请求如实呈现

- **WHEN** 消息内容可解析的请求因无效 key 被拒(401)
- **THEN** 其快照同样生成并进入轨迹,该轮状态由请求记录如实区分

#### Scenario: 无快照请求不进入轨迹

- **WHEN** 请求体超限、读取失败或不可解析,因而未生成快照
- **THEN** 该请求不归入任何会话(归属由快照承载),仅在原始层与请求记录中可查;轨迹视图不得声称覆盖全部请求

### Requirement: session 判定

系统 **必须(MUST)** 按**显式协议标识**判定快照归属的 session:Anthropic 方向取 `x-claude-code-session-id`,OpenAI 方向取 `session-id`/`thread-id`(两种拼写都接受);标识 **必须** 先经规范化(长度上限与字符白名单),不合规标识 **不得** 采信;未携带或不合规的请求 **必须** 归入按天分桶的匿名会话,**不得** 与显式会话混合;**必须** 记录判定来源与判定理由(命中的头名、降级事件、匿名兜底——随快照行落盘)。判定在捕捉时一次性写入,不提供在线重算——纠错依靠理由定位后直接修改数据。**链合兜底(按消息内容推断会话延续)不在本变更范围内**。

#### Scenario: 显式标识归组

- **WHEN** 一串请求携带相同的会话标识头
- **THEN** 它们被归入同一 session,判定来源标记为显式,判定理由记录命中的头名

#### Scenario: 压缩不断链

- **WHEN** 会话发生上下文压缩,新请求与历史快照不再构成前缀关系
- **THEN** 仍归入原 session——判定只依赖标识头,与消息内容无关;压缩不影响会话归属

#### Scenario: 无标识归入匿名会话

- **WHEN** 请求未携带会话标识头
- **THEN** 它被归入按天分桶的匿名会话,判定理由记录匿名兜底,不与显式会话混合

#### Scenario: 非法标识降级为匿名

- **WHEN** 会话标识头超长或含白名单外字符
- **THEN** 该值不采信为显式标识,降级事件留存于判定理由,请求按无标识处理

#### Scenario: 判定理由随行落盘

- **WHEN** 任一快照被写入
- **THEN** 其判定来源与理由随快照行持久化,误判可由理由直接排查,无需重放判定

### Requirement: 异步捕捉零干扰

捕捉(压缩、解析、落库)**必须(MUST)** 与响应时序解耦:**不得** 因捕捉阻塞响应完成或改变响应内容;捕捉失败 **必须** 仅落入网关日志,**不得** 影响请求本身与请求记录。

#### Scenario: 捕捉失败不影响请求

- **WHEN** 捕捉写入发生错误
- **THEN** 客户端仍正常收到完整响应,错误仅出现在网关日志中

#### Scenario: 不阻塞流式响应

- **WHEN** 流式请求进行中
- **THEN** 捕捉不参与响应流的转发时序

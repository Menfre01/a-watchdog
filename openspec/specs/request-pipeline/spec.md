# request-pipeline

## Purpose

定义网关责任链运行框架的行为契约:中间件的注册与组装方式、固定阶段执行顺序、类型化请求上下文的传递约定,以及环节短路的语义。

## Requirements

### Requirement: 中间件注册与固定阶段序

系统 **必须(MUST)** 以「编译期注册 + 配置启用」的方式组装请求处理链:可用中间件在编译期注册(唯一名字 + 构造函数),配置仅控制启用与参数。链 **必须** 按固定阶段序执行:准入(鉴权等)→ 路由/适配(模型目录解析、上游选择)→ 调用(上游请求)→ 响应后处理(记录等)。

#### Scenario: 链按固定阶段序执行

- **WHEN** 一个请求进入网关
- **THEN** 系统依次经过 准入 → 路由/适配 → 上游调用 → 响应后处理,各阶段的相对顺序不因配置启停而改变

#### Scenario: 未注册的中间件无法启用

- **WHEN** 配置引用了注册表中不存在的中间件名字
- **THEN** 系统在配置加载时显式报错,不在请求路径上静默跳过

### Requirement: 配置控制启用与参数

链上每个中间件 **必须(MUST)** 可被配置启用/禁用,并可接收该中间件的配置参数;禁用一个中间件 **不得** 影响其余中间件的执行。

#### Scenario: 禁用一个环节

- **WHEN** 某中间件被配置禁用
- **THEN** 请求经过该阶段时该中间件不执行,其余中间件照常执行

### Requirement: 强类型请求上下文

每个请求 **必须(MUST)** 在单一的强类型请求上下文中传递跨环节数据(至少涵盖:客户端身份、模型目录与上游选择、上游调用结果元数据);环节之间 **不得** 使用无结构的键值容器传递业务数据。

#### Scenario: 环节间数据传递

- **WHEN** 鉴权环节将客户端身份写入请求上下文
- **THEN** 后续环节以类型化字段读取该身份,且响应后处理环节能将其写入请求记录

### Requirement: 环节短路

任一环节 **必须(MUST)** 能够中止处理链并直接产生响应;被短路后,该阶段之后的处理环节(路由/适配、上游调用)**不得** 执行。

#### Scenario: 鉴权失败短路

- **WHEN** 鉴权环节判定客户端凭据无效
- **THEN** 处理链立即中止并返回鉴权错误响应,路由与上游调用均不执行

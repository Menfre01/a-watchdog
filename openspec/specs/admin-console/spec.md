# admin-console

## Purpose

定义内嵌控制台的管理面行为:由单二进制同端口提供服务,单管理员口令鉴权;providers、models、client_keys 与 settings 的配置管理;上游连通性测试;以及只读的「可观测」视图(会话列表、轨迹、工具聚合)。可观测视图的推断值必须标注来源与判据,不得改写记录侧数据。

## Requirements

### Requirement: 内嵌交付

控制台(页面与接口)**必须(MUST)** 由网关同一二进制、同一监听端口提供(以路径前缀区分);使用控制台 **不得** 需要部署任何额外进程或服务。

#### Scenario: 单二进制访问

- **WHEN** 网关以默认参数启动
- **THEN** 通过浏览器访问监听地址下的控制台路径即可打开管理界面

### Requirement: 管理员鉴权

控制台 **必须(MUST)** 以单管理员口令保护;未通过管理员会话校验的请求 **必须** 被拒绝,**不得** 泄露配置内容。

#### Scenario: 未登录访问被拒

- **WHEN** 未持有有效管理员会话的请求访问控制台接口
- **THEN** 返回未授权响应,不返回任何配置数据

#### Scenario: 登录后操作

- **WHEN** 管理员以正确口令建立会话
- **THEN** 可执行全部控制台操作,直至会话失效

### Requirement: 配置管理能力

控制台 **必须(MUST)** 提供 providers、models(模型目录)、client_keys 的增删改查。对 client_keys **必须** 支持新建密钥、停用与删除。对 providers **必须** 提供「测试连接」。

模型目录列表 **必须** 只显示对外模型名、状态与操作。Provider 与上游模型名 **必须** 只在新建或编辑弹窗中出现。

客户端密钥列表 **必须** 只显示名称、状态与操作。密钥前缀与明文 **不得** 出现在列表。

删除 client key 前 **必须** 二次确认，且确认动作 **必须** 要求完整输入该密钥的名称。名称不匹配时 **不得** 删除。

settings **不得** 出现在控制台界面。settings 的读写 **必须** 只经 HTTP 接口进行，接口与数据保留。

#### Scenario: 完成一次接入配置

- **WHEN** 管理员新建 provider、新建引用它的模型条目、新建一个客户端 key
- **THEN** 系统即时按新配置服务请求

#### Scenario: 停用密钥

- **WHEN** 管理员停用某个 client key
- **THEN** 该 key 随即失效

#### Scenario: 删除密钥需要名称确认

- **WHEN** 管理员在删除确认框里输入的文本与该密钥名称不一致
- **THEN** 确认按钮不可用，密钥不被删除

#### Scenario: 删除密钥成功

- **WHEN** 管理员输入完整名称并确认删除
- **THEN** 该密钥从列表消失，持该密钥的请求随即被拒绝

#### Scenario: 列表不显示内部字段

- **WHEN** 管理员查看模型目录或客户端密钥列表
- **THEN** 模型目录只有对外模型名、状态与操作。密钥列表只有名称、状态与操作

#### Scenario: 配置模块不含全局配置分页

- **WHEN** 管理员打开配置模块
- **THEN** 分页只有接入、模型目录、客户端密钥，没有全局配置

### Requirement: 连通性测试

「测试连接」**必须(MUST)** 以 provider 配置的「测试模型」向上游发起一条最小对话请求(1 token 输出),一次验证地址、凭据与模型可用性;并 **必须** 返回成功结果或可读的失败原因(含上游状态码与错误内容)。未配置测试模型时,系统 **必须** 返回明确提示,且 **不得** 发起任何上游调用。

#### Scenario: 测试成功

- **WHEN** 对配置正确(含测试模型)的 provider 执行测试连接
- **THEN** 返回成功结果与实际连通信息(所用端点与模型)

#### Scenario: 测试失败可见

- **WHEN** 对地址错误或凭据无效的 provider 执行测试连接
- **THEN** 返回失败结果并展示可读的错误原因(含上游状态码与错误内容)

#### Scenario: 未配置测试模型

- **WHEN** 对未填写测试模型的 provider 执行测试连接
- **THEN** 返回明确提示,且不发起任何上游调用

### Requirement: 轮次时间轴

轨迹视图 **必须(MUST)** 为每个轮次给出一条共享时间轴。轮次内每条步在该轴上占一根条。条的位置与长度由该步的起始时间与耗时得出。

时间轴 **必须** 标出本轮最慢的步与 token 用量最大的步。同一条步同时满足两者时,**必须** 给出两个标签。轴两端 **必须** 标起点与轮次总时长。

亚秒级的步 **必须** 保底可见。条的最小长度由显示层给出下限。任何步 **不得** 因耗时过短而不可见。

步之间的空隙 **必须** 标注口径。空隙表示工具在客户端执行与等待的时间。它由相邻两步的时间戳差与耗时差推得,不是记录侧实测的独立字段。界面 **不得** 把该空隙称为实测耗时。

#### Scenario: 时间轴给出每步位置

- **WHEN** 读者展开一个含多步的轮次
- **THEN** 每条步在共享时间轴上有一根条,条的起点与长度对应该步的起始时间与耗时

#### Scenario: 极值被标注

- **WHEN** 一轮里存在耗时最长的步与 token 用量最大的步
- **THEN** 这两条步各自带标签。若属同一条步,该步带两个标签

#### Scenario: 亚秒步不消失

- **WHEN** 一轮里某条步的耗时远小于该轮总时长
- **THEN** 该步在轴上仍有可见的条,位置仍可辨认

#### Scenario: 空隙口径可见

- **WHEN** 读者查看步与步之间的空隙
- **THEN** 界面说明该空隙是工具执行与等待的近似口径,不称其为实测值

### Requirement: 失败优先呈现

轨迹视图 **必须(MUST)** 在轮次首次展开时暴露失败。含失败的步 **必须** 自动展开。轮次顶部 **必须** 列出本轮的失败。每条给出位置与失败原因,并 **必须** 可跳到该步。

失败判据 **必须** 只取记录侧字段:状态码 ≥400,或记录侧 `error_kind` 非空。**不得** 用推断字段判定失败。

#### Scenario: 首次展开自动打开失败步

- **WHEN** 读者首次展开一个含失败步的轮次
- **THEN** 该失败步自动展开,失败详情无需额外点击即可看到

#### Scenario: 失败清单可跳转

- **WHEN** 读者点击轮次顶部失败清单中的一条
- **THEN** 视图定位到对应步,并把它带到可视区域中央

#### Scenario: 失败判据只用记录侧字段

- **WHEN** 某步内容与上一步不同,但其状态码与 `error_kind` 均正常
- **THEN** 该步不算失败

### Requirement: 轮次故事线

轨迹视图 **必须(MUST)** 为每个轮次给出一行叙述。叙述按发生顺序重述本轮事实:新输入、继承与新增行数、工具调用数、细分标记与时长。叙述的每一段在存在对应步时 **必须** 可点。点击后视图跳到该步。

叙述 **不得** 引入新语义。每段只重述已有判定与实测值。无法判定时 **不得** 给出结论。

工具调用数属渐进填充层。未取到时 **必须** 省略该段。该情形下 **不得** 显示为零或留空占位。

#### Scenario: 一行概括本轮

- **WHEN** 读者查看轮次列表
- **THEN** 每个轮次给出一行叙述,读作「新输入 → 行数变化 → 工具调用 → 细分标记 → 时长」

#### Scenario: 每段可跳转

- **WHEN** 读者点击叙述中指向某步的片段
- **THEN** 视图定位到该步

#### Scenario: 不引入新语义

- **WHEN** 某轮的分类无法进一步区分
- **THEN** 叙述如实说明不确定,不给「压缩」或「改写」等未经证实的结论

#### Scenario: 工具数未取到时不显示为零

- **WHEN** 轮次的工具调用数尚未渐进填充
- **THEN** 叙述省略工具调用段,不显示 0

### Requirement: 数值呈现纪律

同一事实的数值 **必须(MUST)** 只在一处给出。轮层级给次数时,步层级 **必须** 只给规模。两处 **不得** 给同一数值。

推断得出的数值 **必须** 在文本里带出口径。缺失或不可得的数值 **必须** 统一显示为「—」。该情形下 **不得** 显示 0,也 **不得** 留空。

渐进加载的入口 **必须** 写明代价:要解析的行数或字节数。入口 **不得** 只写「需加载」这类无代价的说法。

#### Scenario: 同一数值不重复出现

- **WHEN** 轮层级已给出压缩次数
- **THEN** 步层级只给压缩的规模(行数与字节数),不重复给出次数

#### Scenario: 缺失值显示为 —

- **WHEN** 某字段缺失或不可得(如行长度列缺列)
- **THEN** 该处显示「—」,不显示 0 且不留空

#### Scenario: 推断值带口径

- **WHEN** 界面给出一个推断得出的数值
- **THEN** 文本里同时给出该数值的判据(如末行两侧字节数、共同前缀行数)

#### Scenario: 加载入口写出代价

- **WHEN** 某字段需解析后才能显示
- **THEN** 入口写明要解析的行数或字节数

### Requirement: 阅读连续性

轨迹视图 **必须(MUST)** 在数据重载后保持读者的阅读位置。已展开的轮次、步与差异块 **必须** 保持展开。重载 **不得** 把视图滚回顶部。

#### Scenario: 重载后展开状态保持

- **WHEN** 视图重新拉取数据(例如切换会话之外的自动刷新或手动重载)
- **THEN** 读者已展开的轮次、步与差异块仍处于展开状态

#### Scenario: 重载后不跳到顶部

- **WHEN** 视图重新拉取数据
- **THEN** 页面滚动位置保持,读者正在看的内容仍在视野内

### Requirement: 会话链汇总

轨迹视图 **必须(MUST)** 在会话层给出链汇总:主链条数与旁路链条数。主链 **必须** 按链归属的判据选定:至少两个非重复步的链中时间最早的一条,没有这样的链时取含会话首步者。主链恒为 1 条。

旁路 **必须** 另外给出步数与 token 用量(in / out),与会话总量并列。占比 **可以** 由界面按已给数值算出,无需新字段。

链汇总 **必须** 标明为推断。视图 **必须** 写清判据:同一条链的判据是 system 指纹与首条 user 指纹两级相同。两侧都相同才归入同一条链。

#### Scenario: 会话头给出链汇总

- **WHEN** 读者打开一个含旁路链的会话
- **THEN** 会话头给出主链条数与旁路链条数,并给出旁路的步数与 token 用量

#### Scenario: 链数标明为推断并带判据

- **WHEN** 读者查看链汇总
- **THEN** 该数值标明为推断,并可读到判据(system 指纹与首条 user 指纹两级相同)

#### Scenario: 一次性自动请求先到时主链仍正确

- **WHEN** 会话的第一步是生成标题请求,主对话在其后反复出现
- **THEN** 主对话所在链计入主链
- **THEN** 生成标题与安全监控都计入旁路链

### Requirement: 链归属不可判定时如实显示

链归属在缺指纹时会退化为不拆分。此时视图 **必须(MUST)** 显示为「—」,并说明原因(缺 system 指纹,链不可分)。视图 **不得** 把退化后的「1 条链」当作事实显示。

#### Scenario: 缺指纹时不冒充单链

- **WHEN** 会话里的步缺 system 指纹,链归属退化为不拆分
- **THEN** 链汇总显示「—」并说明原因,不显示「1 条链」

### Requirement: 链汇总只在轨迹视图

链汇总 **必须(MUST)** 只出现在轨迹视图。会话列表 **不得** 包含链数。链归属需要对每个会话做整段指纹比对,成本随会话数线性放大。这与列表不含轮次数是同一取舍。

轮层级 **可以** 保留「本轮出现的链」标记。该标记 **必须** 写明口径是本轮出现的链,与会话层的「共 N 条链」区分。

#### Scenario: 会话列表不含链数

- **WHEN** 读者查看会话列表
- **THEN** 列表不给出链数,也不为取链数触发整段比对

#### Scenario: 轮级与会话级口径区分

- **WHEN** 读者在同一屏看到轮级链标记与会话级链汇总
- **THEN** 两处文案分别说明「本轮出现的链」与「会话共 N 条链」

### Requirement: 各步的 harness 侧耗时

轨迹视图 **必须(MUST)** 为每条步给出 harness 侧耗时。它的口径 **必须** 写明:该值等于**同链**下一步请求的开始时间减去本步结束时间。

本步结束时间 = 本步开始时间 + 本步耗时(记录侧实测值)。

该值 **必须** 标明为推算。视图 **必须** 说明它含三部分:工具在客户端的执行、客户端自身的处理、轮次边界处人的思考。三者 **不得** 分开显示,视图也 **不得** 把该值称为「工具耗时」,那会让读者以为它只覆盖工具执行。

视图 **必须** 说明该窗口的范围。窗口含客户端在同期为**其它链**所做的工作。它也含同期对**其它端点**的请求,那些请求不生成 step。视图 **不得** 把该值当作该步独占的工作量。

本步耗时 **必须** 标明其口径:记录在**请求体读完**之后开始计时,故本步耗时不含读取请求体的时间。请求体的上传时间因此落在 harness 侧窗口内。

#### Scenario: 每步给出 harness 侧耗时

- **WHEN** 读者查看某一步
- **THEN** 该步给出 harness 侧耗时,并标明为推算

#### Scenario: 口径写明含三部分

- **WHEN** 读者查看该值的口径说明
- **THEN** 说明指出它含工具执行、客户端处理与人的思考时间,且三者不可拆分

#### Scenario: 口径写明窗口的范围

- **WHEN** 读者查看该值的口径说明
- **THEN** 说明指出窗口含同期为其它链所做的工作,也含不生成 step 的其它请求。说明还指出该值不是该步独占的工作量

#### Scenario: 本步耗时的口径写明

- **WHEN** 读者查看本步耗时的口径
- **THEN** 说明指出计时从请求体读完开始,故不含请求体的读取时间

### Requirement: harness 侧耗时在时间轴上的标记

时间轴 **必须(MUST)** 用与实测条不同的样式标出 harness 侧时间段。该段从本步条的右端画到**同链**下一步条的左端。该段 **不得** 使用实测条的实心样式。

该段 **不得** 跨链画:一段 harness 侧耗时 **必须** 只在同链相邻两步之间给出。旁路请求的到达时间 **不得** 算进主路步的 harness 侧耗时。

后继落在下一轮时,超出本轮轴范围的段 **必须** 裁掉,并 **必须** 在提示里说明该值延续到下一轮。数值本身 **必须** 给全量。

#### Scenario: 时间轴以独立样式标出该段

- **WHEN** 读者展开一个有多步的轮次
- **THEN** 每步之后可见一段与实测条样式不同的标记,长度对应该步的 harness 侧耗时

#### Scenario: 不跨链画段

- **WHEN** 本步之后先到达的是另一条链的请求
- **THEN** 该步的 harness 侧耗时只按同链下一步计算,不按那条旁路请求的到达时间计算

#### Scenario: 后继在下一轮时裁掉超出部分

- **WHEN** 同链下一步落在下一轮
- **THEN** 本轮轴上的段止于轴末端,提示说明该值延续到下一轮,数值仍给全量

### Requirement: harness 侧耗时的边界情形

一条链的最后一步没有后继请求。此时该值 **必须(MUST)** 显示为「—」,且 **不得** 画段。

推算结果为负时(并行请求导致后继请求早于本步结束),该值 **必须** 显示为「—」,且 **不得** 画段。该情形 **不得** 显示为 0:它是「不可测」,不是「没花时间」。

#### Scenario: 链末步显示「—」

- **WHEN** 某步是该链的最后一步
- **THEN** 该步的 harness 侧耗时显示为「—」,轴上不画段

#### Scenario: 负值显示「—」而不是 0

- **WHEN** 同链下一步的开始时间早于本步结束时间
- **THEN** 该步的 harness 侧耗时显示为「—」,轴上不画段,且不显示为 0

### Requirement: 混合协议的会话

一个会话里出现多个协议时(同一会话标识下换过客户端),视图 **必须(MUST)** 说明口径。各步按各自的协议记录用量。跨协议的用量 **不得** 直接相加。

每条步 **必须** 能看出它的协议,以便读者在混合协议时逐条判断。

#### Scenario: 混合协议时说明不可相加

- **WHEN** 会话里出现两个及以上协议
- **THEN** 视图给出这一情况,并说明跨协议用量不可相加

#### Scenario: 单协议会话不打扰

- **WHEN** 会话里只有一个协议
- **THEN** 视图只给出该协议,不出现混合协议的说明

### Requirement: 链归属与内容分类的分工写清楚

视图 **必须(MUST)** 让读者分清两件事:链归属决定「这是哪一条链」,内容分类决定「这一步与同链上一步重合多少」。

判定理由或图例 **必须** 至少在一处说明:链归属用稳定指纹(system 前缀加首条 user 前缀),内容分类用整行字节。两者判据不同,故「同一条链」与「零重合」可以同时成立。

#### Scenario: 两件事的说法不混同

- **WHEN** 读者看到某步被标为「无重合」
- **THEN** 界面说明这一步仍属于原链,并指出链数见会话头的链汇总

### Requirement: 可观测菜单

控制台 **必须(MUST)** 提供「可观测」菜单,由**三个只读视图**组成:**会话列表**(跨会话入口)、**轨迹**(单个会话的层级展开)与**工具**(会话级聚合与筛选)。三个视图共用会话级查询缓存;任何视图 **不得** 修改原始层、快照与请求记录,也 **不得** 为展示写入派生数据。视图的层级、字段与视觉语言(实线为实测值、虚线为推断、虚线灰框与虚线下划线为需解析可渐进填充) **必须** 以 `docs/trail-view.html` 为形态基准。

#### Scenario: 菜单结构

- **WHEN** 管理员打开可观测菜单
- **THEN** 可见会话列表、轨迹与工具三个视图;点击会话列表中的会话可进入该会话的轨迹

#### Scenario: 只读约束

- **WHEN** 通过可观测菜单查看任何视图
- **THEN** 原始层、快照与请求记录均不被修改,展示过程不产生派生数据写入

### Requirement: 会话列表视图

会话列表 **必须(MUST)** 支持按客户端原始标识前缀、时间范围与 client key 过滤。原始标识前缀与 client key 两个条件 **必须** 可叠加。每行显示会话标识、**Agent 分类**、首见与末见时间、step 数与累计 token(`steps` 即该会话的请求数。会话归属由快照承载，二者恒等)。

会话标识 **必须** 以短前缀显示(前 8 位加省略号),完整值 **必须** 作为悬停提示与详情页标题。完整标识 **不得** 在列表里铺满整列。

进入详情 **必须** 通过可聚焦的链接完成，链接目标 **必须** 是该会话的片段路径。**不得** 只提供鼠标可点的整行。整行点击 **可以** 作为附加手段保留。

Agent 分类 **必须** 取值于固定集合：**Claude Code**、**Codex**、**DSH**、**Other**。分类由判定理由派生，列表 **不得** 显示逐条的判定来源与理由。

列表 **不得** 显示轮次数。推断轮次需要对每个会话做指纹比对与首行解析，成本随会话数线性放大。轮次数由轨迹视图给出，列表页 **必须** 说明这一取舍。

#### Scenario: 列表与过滤

- **WHEN** 管理员按标识前缀过滤会话列表
- **THEN** 只列出匹配的会话。每行显示 Agent 分类、首末时间、step 数与累计 token

#### Scenario: 按密钥过滤

- **WHEN** 管理员选择某个 client key 作为过滤条件
- **THEN** 只列出该密钥下的会话，其他密钥的会话不出现

#### Scenario: 两个条件叠加

- **WHEN** 管理员同时选择 client key 并输入标识前缀
- **THEN** 只列出该密钥下标识前缀匹配的会话

#### Scenario: 标识显示短前缀

- **WHEN** 管理员查看会话列表
- **THEN** 标识显示为前 8 位加省略号，完整值可在悬停时看到

#### Scenario: 键盘进入详情

- **WHEN** 管理员用 `Tab` 聚焦到某行的会话标识并按 `Enter`
- **THEN** 进入该会话的轨迹视图，地址栏含该会话标识

#### Scenario: Agent 分类来自判定头

- **WHEN** 会话由 `x-claude-code-session-id` 判定
- **THEN** 该行的 Agent 分类显示为 Claude Code

#### Scenario: 无标识归为 Other

- **WHEN** 会话是按天分桶的匿名会话
- **THEN** 该行的 Agent 分类显示为 Other

#### Scenario: 不含轮次数

- **WHEN** 管理员打开会话列表
- **THEN** 列表不显示轮次数，并可见说明其成本原因

#### Scenario: 标识不带密钥前缀

- **WHEN** 管理员查看会话列表或轨迹头部
- **THEN** 标识显示为客户端给的原始串，不以 `<key_id>:` 开头

### Requirement: 轨迹查看

轨迹 **必须(MUST)** 提供单个会话的层级视图。层级为轮次、step 骨架、step 明细。

轮次行 **必须** 含：序号、标题、起始时间、step 数、汇总用量、压缩标记、重复次数、失败步数与工具调用数。

step 骨架 **必须** 含时间、耗时、状态、token 用量、重复标记与增量分类。骨架 **必须** 再含压缩标记、行数与长度变化、新增行数与判定理由。

step 展开后 **必须** 显示请求、响应与工具三段。messages 默认给本轮新增，可切换全量。响应段 **必须** 显示文本、思考、工具请求、停止原因与用量。响应未记录时 **必须** 说明原因。

工具条目 **必须** 显示工具名、核心参数摘要、耗时与状态。条目 **不得** 显示发起步与结果步。参数摘要 **必须** 取最能说明动作的字段。耗时 **必须** 取工具事件的实测值，无事件时标为未知。条目 **必须** 可展开，展开后给入参与结果。入参与结果 **必须** 优先用上报值。缺失时 **可以** 用复原值，并 **必须** 标明来源。

摘要压缩 **必须** 给前后对照：压缩前后的消息序列与行数，以及保留、删除、新增的行数。删除的内容 **必须** 可展开查看。

分叉 **必须** 给差异块。差异块按 LCS 求出，与同链上一步比较。每块 **必须** 标明类型、两侧行号范围与字节数，以及该处每一行的实际内容。每块 **必须** 可独立折叠，单块时默认展开。删除消息时 **必须** 只给旧侧内容，并标明新侧无内容。纯追加 **不得** 产生差异块。

**不得** 仅凭长度变化推断压缩或改写。

上下文清零与无重合 **必须** 各有独立标记与判定理由。旁路链 **不得** 标上下文清零，因为该语义只对主对话成立。首步与后续的无重合 **必须** 使用不同文案。

时间线骨架 **必须** 只解析各步新增区间，**不得** 解析历史消息。轮次标题与工具调用数 **可以** 异步填充，**不得** 阻塞轮次与 step 显示。

记录侧 `error_kind` 非空时，该步 **必须** 显示网关侧归因。归因示例：鉴权拒绝、模型未路由、上游中断。

无快照的请求 **不得** 出现在轨迹中。视图 **不得** 声称覆盖全部请求。

轮次分组、增量分类与重复计数 **必须** 统一标明为推断。工具耗时 **必须** 标明为事件边界实测，含客户端处理。

#### Scenario: 查看完整轨迹

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 从首轮至最新逐轮可见
- **THEN** step 骨架立即显示耗时、token、重复标记与增量分类
- **THEN** 展开后加载工具明细与 messages

#### Scenario: 重复步可见

- **WHEN** 某请求与上一步内容完全相同
- **THEN** 该步按组内序号显示，例如「第 2/3 次相同」
- **THEN** 该步显示自身状态码与判定理由

#### Scenario: 摘要压缩可对照查看

- **WHEN** 管理员展开一个标为摘要压缩的 step
- **THEN** 可见压缩前后的行数与消息序列
- **THEN** 可见被删除区间的内容

#### Scenario: 差异块可查看

- **WHEN** 管理员查看一个分类为分叉的 step
- **THEN** 可见每个差异块的类型与两侧行号范围
- **THEN** 展开后可见该处每一行在相邻两步的内容

#### Scenario: 消息被删除可辨识

- **WHEN** 本步相对同链上一步删除了若干消息
- **THEN** 差异块标为「删除」
- **THEN** 只给旧侧行号与内容，新侧标为无内容

#### Scenario: 上下文清零可辨识

- **WHEN** 主对话在新一轮请求中几乎清空历史，例如执行 `/clear`
- **THEN** 该 step 有独立的「上下文清零」标记与判定理由
- **THEN** 该标记不与普通无重合混同
- **THEN** 旁路链不产生该标记

#### Scenario: 无重合可辨识

- **WHEN** 主对话某 step 与上一步既无共同前缀也无共享尾部
- **THEN** 该 step 标为「无重合」并给出判定理由

#### Scenario: 被拒请求可辨识

- **WHEN** 某请求被鉴权拒绝且其请求体可解析
- **THEN** 该步在其所属会话的轨迹中可见
- **THEN** 该步标明网关侧归因，不因被拒而省略

#### Scenario: 轮次提示

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 每个轮次显示 step 数、汇总用量、压缩标记、重复次数与失败步数
- **THEN** 标题与工具调用数可稍后填充，不阻塞列表显示

#### Scenario: 轮次标题渐进填充

- **WHEN** 管理员打开某会话的轨迹
- **THEN** 轮次先显示骨架，标题与工具调用数稍后填充
- **THEN** 标题取不到时为空，不阻塞显示

#### Scenario: 查看单步 messages 与 tool 明细

- **WHEN** 管理员打开某个 step
- **THEN** 默认显示本轮新增的 messages 与继承行数
- **THEN** 可切换查看全量
- **THEN** 每个工具条目显示名称、参数摘要、耗时与状态
- **THEN** 展开条目可见入参与结果

### Requirement: 工具聚合视图

控制台 **必须(MUST)** 提供**会话级**的工具聚合视图:按工具名汇总调用次数、状态分布(成功 / 失败 / 结果未见)、近似间隔与发起的轮次;视图 **必须** 支持筛选:工具名(片段匹配)、状态、来源(内置 / MCP)。「结果未见」的调用 **必须** 单独呈现,且 **不得** 计入间隔统计。间隔 **必须** 标明为轮间近似(含客户端本地执行与人的思考时间)。聚合 **必须** 由快照现算,**不得** 为它额外写入源数据;跨会话的全局统计不在本变更范围内。

#### Scenario: 聚合与筛选

- **WHEN** 管理员打开工具视图并按状态筛选「失败」
- **THEN** 只列出存在失败调用的工具,汇总数字随筛选条件更新

#### Scenario: 结果未见单独呈现

- **WHEN** 某次调用在后续快照中找不到结果
- **THEN** 该工具行计入「结果未见」,且该次调用不参与间隔统计

#### Scenario: 来源可区分

- **WHEN** 调用的工具名带 `mcp__` 前缀(来自 MCP 服务器)
- **THEN** 其来源标为 MCP,可与内置工具分开筛选

### Requirement: 控制台导航分组

控制台侧栏 **必须(MUST)** 只有两个模块:**可观测** 与 **配置**。两个模块 **必须** 位于同一层级。

配置模块 **必须** 以孤岛同时呈现三个管理区:**接入**、**模型目录**、**客户端密钥**。三个孤岛 **不得** 被分页、折叠或跳转隐藏。每个孤岛 **必须** 有独立标题与主操作,并且只管理该区的数据。孤岛之间 **必须** 用留白分隔,不得用分页替代。

配置页 **不得** 再提供一级标题,一级标题由模块统一给出;孤岛标题用二级层级。

#### Scenario: 侧栏只有两个模块

- **WHEN** 管理员登录控制台
- **THEN** 侧栏只有可观测与配置两项

#### Scenario: 三个管理区同时可见

- **WHEN** 管理员打开配置模块
- **THEN** 接入、模型目录、客户端密钥三个孤岛同时出现在同一页

#### Scenario: 孤岛操作独立

- **WHEN** 管理员在接入孤岛点「新建接入」
- **THEN** 只在接入孤岛内打开弹窗并写入该区数据,另外两个孤岛不受影响

#### Scenario: 配置页无一级标题

- **WHEN** 管理员打开配置模块
- **THEN** 页面只有配置模块的一级标题,三个孤岛各自用二级标题

### Requirement: 统计口径拆分

轨迹统计卡 **必须(MUST)** 先给总计，再给 **主路** 与 **旁路** 的拆分。总计 **必须** 包含旁路。旁路组 **必须** 标注为总计的子集，界面 **不得** 让读者以为两组相加。

总计与拆分 **必须** 各自只出现一次：总计一行给 turns、steps、in/out/cache。拆分一行给主路与旁路的 steps 与 in/out/cache。

#### Scenario: 总计包含旁路

- **WHEN** 会话含旁路步
- **THEN** 总计 steps 等于主路 steps 与旁路 steps 之和，且旁路组标注为子集

#### Scenario: 拆分不重复总计

- **WHEN** 读者查看统计卡
- **THEN** turns 只在总计行出现，主路与旁路行只给各自的 steps 与 token

#### Scenario: 无旁路时不出现拆分

- **WHEN** 会话没有旁路步
- **THEN** 统计卡不显示旁路组，也不显示空的拆分行

### Requirement: 请求指标岛

可观测页 **必须(MUST)** 提供「请求指标」岛，显示所选窗口内的五项数据:

- 请求数
- 错误数与错误率
- 延迟 p50 与 p95
- 缓存命中率
- 输入与输出 token 合计

窗口 **必须** 可选 1 小时、24 小时、7 天、全部，默认 24 小时。

错误率 **必须** 按「状态码 4xx 以上或带错误类型的请求数 ÷ 请求总数」计算。缓存命中率 **必须** 按「缓存读取 ÷(输入 + 缓存读取)」计算，分母为 0 时显示 0。

分位数 **必须** 取升序延迟的第 `ceil(p × n)` 个样本。窗口内样本少于 20 个时，界面 **必须** 说明分位数参考意义有限。

#### Scenario: 显示窗口指标

- **WHEN** 管理员打开可观测页
- **THEN** 看到默认 24 小时窗口内的请求数、错误率、p50、p95、缓存命中率与 token

#### Scenario: 切换窗口

- **WHEN** 管理员点选 7 天
- **THEN** 指标按最近 7 天重新计算

#### Scenario: 样本不足

- **WHEN** 窗口内请求少于 20 个
- **THEN** 界面说明分位数参考意义有限

### Requirement: 时间构成与工具段

轨迹统计卡 **必须(MUST)** 给出两段时间的合计:**模型** 与 **工具**,并给出工具占机器时间的比例。

- 模型段取各步 `latency_ms` 之和，是实测值。
- 工具段取已配对工具事件的区间并集，口径是事件边界，**必须** 标注含客户端处理。并行调用 **不得** 重复计时。工具 **必须** 归到生成该调用的步，不得归到它的下一步。工具段 **不得** 越过 harness 段。窗口超出时按 harness 截断显示。
- 两段 **必须** 用行内数字显示，不得单独占用时间轴色条。
- 输入时间与空闲时间 **不得** 进入构成。它们仍由客户端采集,供需要时查阅。
- 工具事件数少于轨迹中的工具调用数时, **必须** 给出一条数据完整性提示,说明工具耗时可能偏低。

两段 **必须** 各自给出数值与数量：模型按步数，工具按已配对调用数。

#### Scenario: 两段都有数据

- **WHEN** 会话含模型请求与工具调用
- **THEN** 统计卡只显示模型与工具两段合计与数量

#### Scenario: 没有工具调用

- **WHEN** 会话全程没有工具调用
- **THEN** 构成条省略工具段，统计卡不显示工具耗时

#### Scenario: 时间轴工具段

- **WHEN** 某步发起了工具调用且有配对的工具事件
- **THEN** 该步的时间轴在模型条之后出现工具段，悬停显示该段时长

### Requirement: 就地说明

轨迹 **必须(MUST)** 在每个非直观符号的出现处给出说明。集中式图例不 **得** 作为唯一说明手段。

时间轴 **必须** 在轴下方写明口径，包括覆盖范围与 harness 段的算法。斜纹段、工具色块与 harness 数值 **必须** 带悬停提示。分类徽标 **必须** 用自身提示说明含义。

说明文字 **必须** 短于两句。说明 **不得** 重复页面其它位置已有的信息。

#### Scenario: 轴口径就地可见

- **WHEN** 读者看到时间轴
- **THEN** 轴下方可见覆盖范围与 harness 算法的说明

#### Scenario: 符号带提示

- **WHEN** 读者把鼠标停在斜纹段、工具色块或分类徽标上
- **THEN** 出现对应的含义说明

#### Scenario: 新增符号

- **WHEN** 页面新增一个非直观符号
- **THEN** 该符号在出现处带说明，不依赖集中式图例

### Requirement: 可观测导航状态

可观测模块 **必须(MUST)** 用地址栏表达当前位置。会话标识 **必须** 出现在片段路径中，视图面板(trace 或 tools)**必须** 出现在查询参数里。刷新或通过浏览器前进后退 **必须** 回到同一会话与同一面板。**不得** 引入第三方路由依赖。

从详情返回列表时，列表 **必须** 保活：滚动位置 **必须** 恢复，选中的行 **必须** 滚回视野。列表 **不得** 因进入详情而被销毁重建。

焦点 **必须** 可回收：进入详情时焦点落到详情标题。返回时焦点落回触发进入的那一行。被保活隐藏的列表 **不得** 继续暴露读屏播报区域。

#### Scenario: 刷新直达会话

- **WHEN** 管理员在某个会话的轨迹视图刷新页面
- **THEN** 仍在同一会话的同一面板，列表与详情的相对位置不变

#### Scenario: 浏览器后退回列表

- **WHEN** 管理员从详情按浏览器后退
- **THEN** 回到列表，滚动位置与进入前一致

#### Scenario: 焦点回收

- **WHEN** 管理员用键盘进入详情后返回
- **THEN** 焦点回到刚才进入详情的那一行

### Requirement: 控制台外壳

控制台 **必须(MUST)** 提供可折叠的侧栏导航。展开态显示图标与文字，折叠态只显示图标并保留全部入口。折叠状态 **必须** 在刷新后保持。

主内容区 **必须** 随视口宽度自适应：宽度不足时 **不得** 产生整页横向滚动。表格 **必须** 在自身容器内横向滚动，操作列在横滚后仍可到达。

内容区 **不得** 依赖固定像素宽度上限。大屏下多出的空间用于放宽列距，不用于增加留白。

#### Scenario: 折叠后入口不丢失

- **WHEN** 管理员把侧栏折叠为图标态
- **THEN** 全部导航入口仍可见可点，主内容区相应加宽

#### Scenario: 折叠状态保持

- **WHEN** 管理员折叠侧栏后刷新页面
- **THEN** 侧栏仍为折叠态

#### Scenario: 窄屏不整页横滚

- **WHEN** 视口宽度为 375px 时打开任一配置页
- **THEN** 页面不出现整页横向滚动，表格在自身容器内横向滚动

#### Scenario: 长值不撑破表格

- **WHEN** 表格某单元格的值(如 Base URL)长于列宽
- **THEN** 该值截断显示，单元格不撑宽表格

### Requirement: 主题切换

控制台 **必须(MUST)** 同时提供暗色与亮色主题，并以暗色为默认。首次访问时初始主题 **必须** 取自系统的 `prefers-color-scheme`。管理员手动选择后，选择 **必须** 在刷新后保持。

主题切换 **必须** 同步调整页面底色与原生控件配色(滚动条、输入框、下拉框),**不得** 只替换文字颜色。主题切换 **不得** 触发页面重新加载，也 **不得** 丢失当前视图状态。

#### Scenario: 首次访问跟随系统

- **WHEN** 系统偏好为暗色，管理员首次打开控制台
- **THEN** 控制台以暗色主题显示

#### Scenario: 手动选择后保持

- **WHEN** 管理员从暗色切到亮色并刷新页面
- **THEN** 控制台仍为亮色

#### Scenario: 原生控件同步

- **WHEN** 管理员处于暗色主题并聚焦文本输入框
- **THEN** 输入框的背景与文字为暗色配色，不出现白底输入框

#### Scenario: 切换不丢状态

- **WHEN** 管理员在展开的轨迹视图里切换主题
- **THEN** 展开的轮次与滚动位置保持不变

### Requirement: 弹窗式配置编辑

控制台 **必须(MUST)** 以弹窗承载配置类的新建与编辑:providers 与 models 的新建与编辑、client_keys 的新建。未打开弹窗时，配置区 **不得** 常驻显示编辑表单。

弹窗 **必须** 满足:

- 打开时焦点落在首个输入控件。
- `Esc` **必须** 关闭弹窗。关闭后焦点 **必须** 回到触发按钮。
- 弹窗打开期间，背景内容 **不得** 可滚动，也不 **得** 可聚焦。
- 保存失败时，错误 **必须** 显示在弹窗内，弹窗 **不得** 关闭，已填内容 **不得** 丢失。
- 保存成功后，弹窗 **必须** 关闭并刷新列表。

#### Scenario: 列表页不常驻表单

- **WHEN** 管理员进入 providers 页
- **THEN** 页面只显示列表与「新建」入口，编辑表单只在弹窗中出现

#### Scenario: Esc 关闭并回收焦点

- **WHEN** 管理员打开新建弹窗后按 `Esc`
- **THEN** 弹窗关闭，焦点回到「新建」按钮

#### Scenario: 保存失败不丢输入

- **WHEN** 管理员提交的 provider 名称重复，服务端返回错误
- **THEN** 弹窗保持打开并显示该错误，已填字段内容不变

#### Scenario: 密钥新建也走弹窗

- **WHEN** 管理员在客户端密钥孤岛点「新建密钥」
- **THEN** 用途名称在弹窗内填写，确认后才新建密钥

### Requirement: 可访问性与数值显示基线

控制台 **必须(MUST)** 满足下列界面基线:

- 所有可点击的展开行与标题 **必须** 是可通过键盘操作的原生控件。
- 不具备原生控件时，**必须** 提供等价键盘处理与 `aria-expanded` 状态。
- 全部交互元素 **必须** 有可见焦点样式，使用 `:focus-visible`。
- 表单控件 **必须** 有对应的标签。密码与新密钥字段 **必须** 标注 `autocomplete`。代码类字段 **必须** 关闭拼写检查。
- 异步结果(加载完成、保存结果、错误) **必须** 通过 `aria-live` 区域播报。
- 数值列 **必须** 使用等宽字体与 `tabular-nums`。不同位数对齐。
- 时间 **必须** 经 `Intl.DateTimeFormat` 格式化。可能出现千分位的计数 **必须** 经 `Intl.NumberFormat` 格式化。带单位的紧凑数值(如 `45ms`、`1.2KB`)与缩写计数(如 `1.2k`)保留既有写法。
- 装饰性图标与折叠箭头 **必须** 对辅助技术隐藏。

#### Scenario: 键盘可展开轮次

- **WHEN** 管理员用 `Tab` 聚焦到某个轮次的标题并按 `Enter`
- **THEN** 该轮次展开，读屏可以识别其展开状态

#### Scenario: 错误对读屏可见

- **WHEN** 保存 provider 失败
- **THEN** 错误信息出现在 `aria-live` 区域中

#### Scenario: 数字列对齐

- **WHEN** 会话列表显示不同位数的 token 数
- **THEN** 各数值按位对齐，不因位数变化左右跳动

### Requirement: 用量口径与协议标记

轨迹视图 **必须(MUST)** 给出该会话用到的协议。协议 **必须** 出现在会话层,读者无需逐条展开即可看到。

用量列的口径随协议不同,视图 **必须** 在界面上写明这一点:

- Anthropic:`in` 是 `input_tokens`,**不含**缓存。`cache` 是缓存读与缓存写之和。`in + cache` 等于总输入。
- OpenAI 兼容与 DeepSeek:`in` 是 `prompt_tokens`,**已含**缓存命中。`cache` 是 `in` 的子集。`in + cache` 会重复计数。

口径文案 **必须** 取自单一来源,由原型与冒烟脚本共用,不得到处各写一份。

#### Scenario: 会话给出协议

- **WHEN** 读者打开任一轨迹视图
- **THEN** 会话层给出该会话用到的协议

#### Scenario: 协议标记写明两种口径

- **WHEN** 读者查看协议标记的提示
- **THEN** 可见 Anthropic 与 OpenAI 兼容两套口径,且写明各自 `in` 的含义与能否相加

#### Scenario: 只标口径不改数字

- **WHEN** 读者查看用量列
- **THEN** 数值与记录侧一致,视图不重算也不改写它们

### Requirement: 分类徽标的显示用词

控制台 **必须(MUST)** 用「无重合」称呼分类 `chain`,**不得** 用「新链」称呼它。该分类的含义是:本步与**同链**上一步既无共同前缀,也无共享尾部。

判定理由 **必须** 陈述这一事实。理由 **不得** 出现「新链」这一说法,那会与链归属的「链」混同。

轮级标记 **必须** 改称「不相交」:该标记同样由分类 `chain` 推导,含义是「本轮与上一步不相交」。

内部键 **必须** 保持 `chain`:改词 **不得** 改动接口、数据与历史快照。

#### Scenario: 徽标用新词

- **WHEN** 读者查看某步的分类徽标
- **THEN** 该分类显示为「无重合」,不显示「新链」

#### Scenario: 判定理由陈述事实

- **WHEN** 读者查看该分类的判定理由
- **THEN** 理由说明它与同链上一步无共同前缀也无共享尾部,并且不出现「新链」这一说法

#### Scenario: 轮级标记改称不相交

- **WHEN** 某轮由该分类的步开启
- **THEN** 轮级标记显示为「不相交」

#### Scenario: 内部键不变

- **WHEN** 比较改词前后的接口响应
- **THEN** 分类键仍是 `chain`,只有显示词与文档用词变化

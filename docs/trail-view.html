Session 轨迹预览

静态原型:数据为示例值。骨架与汇总先出,tool 明细与 messages 在展开时才"加载"。
怎么读:虚线紫框是推断字段(指纹比对得出),其余为实测值。 关键约束:网关只存请求体、不存响应体——每个 step 的「请求新增」是事实, 「响应」是从下一轮请求的历史消息反推的(客户端把上一轮的 assistant 消息拼回了 messages)。 重复请求按组标记(第 n/N 次相同):判据是内容与上一步完全相同,不必然是失败后重发。摘要压缩(turn 4,行数骤降,展开给出前后对照与被移除内容)与 分叉对照 差异块(turn 5,按 LCS 求出、与同链上一步比较,每块可独立折叠:改动 / 删除 / 新增三类)。 末行更新(turn 9,行数不变且只剩末行不同:变长与变短都算,方向由末行两侧的字节数给出,故徽标写「末行扩展 +NB」「末行收缩 −NB」而非笼统的「分叉」)。 继承行表示本轮复用了历史消息但未解析。 turn 行的压缩/重复/失败标记是指纹级(零解析);「N 个工具」与虚线标题需解析该轮新增行, 在骨架渲染后渐进填充。 时间轴(每轮一条共享轴:每步一根条,标最慢与最多 token 的步;轴含旁路请求,条间空白为工具执行与等待的近似)、 失败清单(固定在轮次顶部,判据只取记录侧字段)、一行叙述(每段指向对应步)与 分类分布条(分项之和等于步数,细分另列)、链汇总(主链 1 条 + 旁路链,并按步与 token 给出旁路占比; 缺 system 指纹时链数显示「—」并说明原因)见本轮改动的形态;线型与徽标的含义见页首图例。 harness 侧时间用斜纹段标出:它从本步条的右端画到同链下一步的左端,含工具执行、客户端处理与人的思考, 三者不可拆分;链末步没有后继,数值显示「—」,后继落在下一轮时该段止于轴末端并在提示里说明。

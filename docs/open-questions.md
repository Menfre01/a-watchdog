# 待定问题：主链参与边界

- 状态：搁置，等待更多客户端样本
- 影响：轨迹视图的主链 / 旁路归属
- 关联规范：[trajectory-analysis](../openspec/specs/trajectory-analysis/spec.md)、[admin-console](../openspec/specs/admin-console/spec.md)
- 当前决定：暂不改判据，先收集样本

## 问题

哪些链可以参与主链竞争。当前判据在 Claude Code 样本上有效。样本太少，无法确认它在重试、重命名、并发反序和单轮会话下是否稳定。

## 当前判据

`trace.AnalyzeSession` 的规则：

1. 排除不足两个非重复步的链。重复步指 `DeltaKind == retry`。
2. 在剩余链中取最早出现的一条为主链。
3. 没有剩余链时，取含会话首步的链。

“最早”按链首次出现的时间计算。

## 已知失败形态

- **标题链重试或重命名**：标题链可能达到 2 个非重复步，并因为最早出现而夺取主链。
- **监控链先到**：安全监控与主对话几乎同时发出。并发顺序反转时，监控链可能成为最早重复链。
- **单轮主对话加重复监控**：主对话只有 1 步，监控有 2 步时，监控会赢。
- **子 agent**：通常晚于主对话出现，当前样本中没有风险。

## 现有样本

网关库中只有 3 个 Claude Code session，共 145 条请求。只有 1 个多链 session。

多链 session `1:141983eb-874a-4072-abbf-7bfd343e6efb`：

| 链 | 步数 | 首步时间（UTC） | 首请求特征 |
|---|---:|---|---|
| 标题 | 1 | 13:04:08.939 | user 为 `<session>…</session> Write the title…`。body 约 3.9 KB。timeout 600。无 agent-id |
| 主对话 | 84 | 13:04:08.965 | user 为 system-reminder。body 约 192 KB。timeout 600。无 agent-id |
| 安全监控 | 33 | 13:04:12.050 | system 为 “You are a security monitor…”。body 约 153 KB。timeout 60 |
| 子 agent | 18 | 13:22:17.745 | system 为 “You are a Claude agent…”。带 `X-Claude-Code-Agent-Id`。body 约 77 KB |

标题链比主链早 26 ms。监控链晚约 3.1 秒。子 agent 晚约 18 分钟。

另外两个 session 只有主链，分别为 6 步和 3 步。

## 为什么现在不定

- 只有 1 个多链 session，无法区分“判据正确”与“样本碰巧正确”。
- 标题重试、标题重命名、监控先到都没有出现。
- 样本只来自 Claude Code，一个客户端。
- 头部特征可能随 Claude Code 版本变化，不能直接写进通用判据。
- 现有规范要求链归属与协议无关。按客户端头部排除会破坏这个约束。

## 候选方向

### 方向 A：保持现判据，先加诊断（推荐）

不改 `AnalyzeSession`。离线统计每个链的特征，等样本足够后再决定。

优点：没有行为风险。  
缺点：已知边界问题仍然存在。

### 方向 B：按请求形态给资格

只允许“完整对话请求”参与主链竞争：

- 无 `X-Claude-Code-Agent-Id`。
- 超时不是 60 秒。
- body 包含完整对话与工具定义。
- 首条 user 不是标题生成指令。

优点：能直接排除标题、监控与子 agent。  
缺点：规则属于 Claude Code 适配层，不是通用判据。需要新规范与适配器设计。

### 方向 C：按语义识别派生请求

解析 system / user 文本，识别“生成标题”“安全监控”“子 agent”。

优点：可读。  
缺点：文本随版本变化，容易误判。不建议作为核心判据。

### 方向 D：按长度或时间跨度选主链

监控可能比主链长，时间跨度也可能接近。旧反例已经否掉长度判据。不建议。

## 需要收集的字段

每条链至少记录：

- 链编号与首步序号。
- 步数与非重复步数。
- 首末时间。
- 首请求的 `X-Claude-Code-Agent-Id` 是否存在。
- 首请求的 `X-Stainless-Timeout`。
- 首请求 body 字节数与工具数。
- system 指纹前缀的哈希。
- 首条 user 文本前缀的哈希。

正文不落库。用哈希、长度与前缀代替。

## 重新评估的触发条件

满足任一条件即可重新评估：

- 累计至少 20 个多链 session。
- 接入至少一个其他客户端，并有真实多链样本。
- 观察到一次标题重试、标题重命名、监控先到或单轮主链 1 步加监控 2 步。
- 头部特征在 3 个客户端上稳定。

重新评估时先补诊断报告，再决定是否提案修改判据。

## 结论

当前不改判据。先保留 `AnalyzeSession` 的行为，收集多客户端样本。等出现足够多链样本或已知失败形态后，再决定资格规则。
